# Plan: 128-token chunks with sentence-overlap

## 1. Misunderstanding clarified

Current code (`src/lucas_v2/chunking.py:19-71`) does **NOT** do 128 tokens/chunk:
- It flushes on **every** cue text ending with `.`/`;` (`_ends_sentence`), so typical
  chunks are 1 cue = 5-15 tokens, far below 128.
- The `max_tokens=128` check is only an emergency cap, and it flushes
  `pending` as-is with **zero overlap** (disjoint `seq_no 0..N`).

Wanted behavior (confirmed):
- **Pack to ~128 tokens** per chunk ("Fill to ~128 tokens"), not early-flush.
- **Clean cut** if the 128-token window ends on a full sentence (`… .` or `… ;`):
  next chunk starts after.
- **Truncated cut** otherwise: next chunk **overlaps** and restarts from the
  beginning of the truncated (interrupted) sentence.

## 2. Constraint: paraphrase-multilingual-MiniLM-L12-v2

Verified via HuggingFace model card:
- `SentenceTransformer((0): Transformer({'max_seq_length': 128, ...}) BertModel, ...)`.
- Hard limit = **128 WordPiece tokens including `[CLS]`/`[SEP]`** → ~126 usable.
- Longer inputs are **silently truncated** by the model (information loss).

Consequence for this task:
- Keep current `count_tokens = len(text.split())` (whitespace, V1) — no new dep.
- Whitespace count ≠ WordPiece count (esp. French subwords, accents, punctuation).
  Whitespace **undercounts** vs WordPiece, so a 128-whitespace chunk may be
  >128 WordPiece and get truncated at embedding time.
- Plan keeps the chunking **algorithm tokenizer-agnostic**: only `count_tokens()`
  changes later. Future swap to `transformers.AutoTokenizer(paraphrase-multilingual-MiniLM-L12-v2)`
  is a 1-function change, no algorithm rewrite. Optionally use `max_tokens=126`
  later to reserve special tokens.

## 3. Sentence-start: two options compared (as requested)

Sentence end = current rule unchanged: text (rstripped) ends with `.` or `;`
(`_ends_sentence`). Sentence start = first word/cue after the last such boundary.

### Option A — cue-level restart (RECOMMENDED)
- On truncation, scan the current window's cues backwards for the last cue whose
  accumulated text ends with `./;`. Next chunk starts at the **next cue**.
- If no cue boundary exists in the window, advance by 1 cue (forced cut, no overlap).
- Pros: trivial; `start_s`/`end_s` stay exact (whole cues, `Chunk.start_s=cues[0].start_s`);
  no text surgery; no infinite-loop risk if guarded; matches SRT granularity.
- Cons: coarser overlap — if one cue holds several sentences, the whole cue is
  repeated (a few extra tokens duplicated, harmless for retrieval).
- Cost: ~10 lines.

### Option B — word-level restart
- Find the last `.`/`;`-terminated **word** inside the chunk text; next chunk
  restarts at the following word, possibly **mid-cue**.
- Pros: tighter 128-token packing, minimal duplication.
- Cons: splits cues → `start_s`/`end_s` become ambiguous (partial cue timing);
  need char/word→cue re-mapping; fragments like `"puissant. c'est un..."` mid-cue;
  more edge cases (abbreviations, `...`, numbers); ~40+ lines + new tests.
- Verdict: overkill for embedding recall; the duplication saved is negligible
  vs complexity. **Reject for now.**

Decision: implement **Option A**.

## 4. Implementation

### 4.1 File: `src/lucas_v2/chunking.py` (only prod file touched)
Rewrite `chunk_cues(cues, max_tokens=128)` as sliding window with index `i`:

```
i = 0; seq_no = 0; chunks = []
while i < len(cues):
    # 1. Grow j while tokens <= max_tokens
    j = i; text = ""
    while j < len(cues) and count_tokens(join(i..j)) <= max_tokens:
        j += 1
    # j is first index that overflows, or len(cues)
    end = j - 1  # last fitting cue
    if end < i:  # single cue > max_tokens alone
        end = i  # emit oversize single-cue chunk (same as today), i += 1
        continue/emit
    window_text = join(i..end)
    if _ends_sentence(window_text) or end == len(cues)-1:
        emit(i..end); i = end + 1          # clean cut, no overlap
    else:
        # truncated: backtrack to last sentence boundary inside window
        k = last index in [i..end] where join(i..k) ends with ./;
        if k is not None and k >= i and k < end:
            emit(i..end); i = k + 1        # overlap: cues k+1..end repeated
        else:
            emit(i..end); i = end + 1      # no boundary → forced cut, avoid loop
    seq_no += 1
```

Details:
- Join with single spaces (keep `_flush` as-is).
- Overlap size is dynamic = `end - (k+1) + 1` cues (only the truncated tail),
  not a fixed stride. Guarantees `i` strictly increases every iteration (no infinite loop).
- Keep `_ends_sentence` and `_flush` unchanged. Keep `count_tokens` whitespace.
- Keep signature `chunk_cues(cues, max_tokens=128)`; caller
  `src/lucas_v2/__init__.py:102` needs **no change**.
- Update docstring to describe pack-to-128 + overlap rule.
- `Chunk.tokens` = `count_tokens(text)` may rarely exceed 128 by one cue in the
  single-oversize-cue edge case (document it; same as today's behavior).
